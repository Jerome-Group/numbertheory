# Number Theory verification map

Run the real built app through [the skill](../SKILL.md). All five domains use the same owned foreground instance and fresh browser contexts. Evidence goes to a new absolute directory outside the repository. The script enumerates lesson, path, checkpoint, view, and lab records from the existing verification map and source loader. Do not maintain a second ID inventory here.

| Domain | User outcomes | Driver feature |
| --- | --- | --- |
| [Discovery](discovery.md) | All six views, diagnostic, search, paths, checkpoints, reference, course | `discovery` |
| [Teaching](teaching.md) | All 83 lessons, canonical and legacy entries, proof annotations, reasoning, practice | `teaching` |
| [Practice and progress](practice.md) | Review worksheet, explicit marks, backup, text and file restore, reset, invalid-import atomicity | `practice` |
| [Exact labs](labs.md) | All 20 Studio entries across 14 types, exact positive and negative results | `labs` |
| [URLs and native tools](urls.md) | Shared inputs, history, malformed URL recovery, drawer and keyboard, optional native WebMCP | `urls` |

Each feature document has exactly four H2s. `Preconditions` names any required state. Capture actions and asserted results, plus screenshots, DOM, ARIA, traces, and exact identity. A missing precondition is not a pass through another entry point. The report lists all existing coverage obligations, including those requiring independent browser or mathematical review.

All three viewport profiles run for every domain. Phone and tablet additionally run the drawer journeys. Current automation uses reduced motion. Forced colors, print, additional viewport widths, native accessibility inspection, storage denied or corrupt fixtures, native tools, semantics, and production need separate evidence. Keep those report rows not-evaluated until observed.
